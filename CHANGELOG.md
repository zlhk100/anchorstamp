# Changelog

All notable changes to this project are recorded here. There are no
releases yet; everything below is on the `main` branch.

## Unreleased

### Library and bridge

- `anchorstamp`, the library. `exec_evidence` runs one command and returns
  its outcome with what backs it: when the command was spawned and reaped,
  a join reference whose subject comes from platform state (process id,
  boot clock before the spawn and after the reap, a digest of the
  executable path, the boot id); otherwise a local result with the reason.
  The library runs inside the measured domain and is not a trusted
  component.
- `anchorstamp-exec`, a command-line bridge to the library for agent
  frameworks written in other languages. Also not trusted.
- `anchorstamp-core`, the record types and their wire encoding.
- `exec_loop`, an example that runs a program many times and logs each
  exec, for timing and coverage tests.

### Reader

- `anchorstamp-verify`, the reader. It turns each evidence source into one
  common form and joins the library's claims against it, one outcome per
  claim and one per observation no claim accounts for. It is pure: no
  network, no clock, no randomness. Malformed evidence is excluded and
  counted, never an error.
- Kernel evidence is accepted only under TPM quotes checked against an
  attestation key the operator pins locally, never one taken from the
  evidence.

### Evidence sources

- Software source: `anchorstamp-observe-audit`, the reference observer.
  It reads Linux audit exec records through a descriptor opened before it
  drops privilege and writes chained, unsigned records. It accepts nothing
  from the measured account. Its position and coverage are self-declared.
- Kernel source: `anchorstamp_exec`, a kernel module that turns every
  successful exec into a record measured by IMA, which extends a TPM PCR.
  Records carry a per-load sequence number; losses are counted and
  reported; a separate debug build injects faults for testing. The module
  is licensed GPL-2.0 OR MIT.
- Root scripts for the kernel source: the IMA policy rule, load and
  unload, a fixture and the fault build's loader.

### Collector

- `collector/collect.sh` gathers the IMA measurement list and TPM quotes
  over it, made by a TPM-resident attestation key, into one bundle.
- `verify/verify-anchor.py`, a Python checker of a bundle against its
  quotes, for the first record version.

### Demo

- `demo/run.sh`, the run harness. Run as root, it runs one scenario as an
  unprivileged measured account with the observer outside it, then
  reports.
- `agentsim`, a scripted stand-in for an agent framework, and ten
  scenarios: honest, shadow, subagent, pipeline, forger, evade, burst,
  longpath, escalate, tamper.
- A real agent framework (smolagents) as the measured party, through the
  bridge, installed only from a hash-locked requirements file.
- `demo-report`, which states in words what one run's evidence supports,
  with the limits printed on every report.

### Conformance vectors

- `verify/vectors`: conformance vectors as hex text with their pinned
  digests, generated by `gen_vectors.py` and checked by the reader's tests.
  The quote signatures in them are made with a published test key.

### Project

- Code licensed MIT OR Apache-2.0; documentation CC BY 4.0; the kernel
  module GPL-2.0 OR MIT, with the GPL-2.0 text. SPDX headers in every file
  that can carry one.
- A coding standard and its check target, `scripts/check.sh` (clippy,
  shellcheck, ruff, cargo-deny, checkpatch, sparse, writable statics).
- A CI workflow that builds and tests on stable and on the minimum
  supported Rust version (1.87) and runs the check target.
- A security reporting policy.
